# المرتجعات واللوجستيات العكسية — المرحلة 22

## المعمارية والثبات التاريخي

`ReturnRequest` تجميع مشترك يشير حصراً إلى `Order` أو `PosSale`. يشير `ReturnItem` إلى البند التجاري الأصلي، ويشير `ReturnItemBatchAllocation` إلى تخصيص التشغيلة الأصلي والتشغيلة نفسها. لا تُعدل الطلبات أو مبيعات POS أو مدفوعاتها أو حركات صرفها أو قرارات الوصفة أو نتائج السلامة.

الحالات هي `draft، submitted، under_review، approved، received، refunded، closed` وحالتا النهاية `rejected، cancelled`. الانتقالات التشغيلية خدمات صريحة مقفلة صفياً وليست إسناد حالة من HTTP.

## الأهلية والكميات

المصدر المؤهل طلب `delivered` أو بيع POS `completed`. تُقفل المعاملة الأصلية عند الإنشاء ويُمنع مجموع الكميات المطلوبة غير المرفوضة/الملغاة من تجاوز المصروف، مع دعم عدة مرتجعات جزئية. لا توجد مدة إرجاع مفترضة لأن الإعدادات الحالية لا تحمل سياسة تنظيمية؛ تضاف لاحقاً كإعداد صريح.

يحفظ البند المنتج الأصلي والمصروف/البديل، والكميات المطلوبة والمعتمدة والمستلمة، وسعر الوحدة، ونصيب الخصم والضريبة، والقيمة القابلة للاسترداد، والسبب والحالة والتصرف والفحص.

## التسعير والاسترداد

لا تُقرأ الأسعار الحالية. يوزع صافي البضاعة الأصلية على البنود بنسبة القيمة الإجمالية بخوارزمية أكبر باقٍ وكسر التعادل بمعرف البند، ثم على الوحدات بأعداد القروش الصحيحة. يدخل خصم المنتج والسلة والكوبون والخصم اليدوي في صافي البضاعة. ضريبة POS محفوظة منفصلة (صفر حالياً). رسوم التوصيل غير قابلة للاسترداد افتراضياً ولا ترد تلقائياً مع مرتجع جزئي.

`Refund` سجل مالي جديد غير قابل للحذف. النقد يكتمل فوراً ويرتبط بجلسة الصندوق المفتوحة للمنفذ. بطاقة الجهاز الخارجي تنشأ `pending` ولا تكتمل إلا بمرجع غير حساس وتأكيد صريح؛ لا توجد بوابة دفع أو ادعاء تحقق. في الدفع المختلط يحدد المشغل الطريقة، مع سقف المقبوض الأصلي للطريقة ناقص السابق. لا تخزن PAN أو CVV.

تسوية الصندوق: رصيد الافتتاح + المبيعات النقدية − الاستردادات النقدية. الجلسات المغلقة لا تتغير؛ الاسترداد اللاحق يرتبط بجلسة المنفذ الحالية.

## التشغيلات والتصرف والفحص

يقرأ الاستلام تخصيصات حجز الطلب المستهلكة أو تخصيصات بيع POS بترتيب المعرف، ويقفلها مع التشغيلات والمنتجات. لا تعاد كمية إلى تشغيلة أخرى.

- `restock`: يزيد التشغيلة الأصلية إذا كان المنتج غير مفتوح والتشغيلة غير منتهية وغير معزولة.
- `quarantine`: يزيد الحيازة الفعلية و`returned_quarantine_quantity` غير القابلة للتخصيص.
- `write_off` و`destroy_pending`: يسجلان أثراً ولا يجعلان الكمية قابلة للبيع.

كل قرار ينشئ حركة `return_*` بمفتاح idempotency ويزامن تجميع المنتج. لا تتغير الصلاحية أو هوية التشغيلة. الدواء الموصوف يحتاج فحص صيدلي مسجل؛ لا يعاد تشغيل محرك السلامة ولا تتغير الوصفة أو الاستبدال.

## الصلاحيات والتدقيق

- العميل يطلب لطلبه المسلم فقط.
- مشغل POS أو مدير الطلبات يبدأ المرتجع.
- مدير الطلبات أو المدير يعتمد/يرفض.
- الصيدلي يفحص الدواء.
- مدير المخزون أو الصيدلي أو المدير يرحل التصرف.
- المدير ينشئ ويؤكد الاسترداد.
- المدير ومدير الطلبات ومدير المخزون يرون التقرير وCSV.

تسجل أحداث التدقيق الإنشاء والإرسال والاعتماد/الرفض والاستلام والفحص والتصرف وإنشاء/اكتمال الاسترداد. الإيصال عربي RTL ويطبع من المتصفح ولا يعرض معلومات سريرية.

## التزامن والحدود

تقفل الخدمات المصدر والمرتجع والتخصيصات والتشغيلات، وتطبق قيود قاعدة البيانات والمفاتيح الفريدة. ترحيل الاستلام معاملة واحدة كاملة، والاسترداد معاملة منفصلة. إعادة المفتاح نفسه لا تكرر المخزون أو المال.

التقرير تشغيلي وليس تحليلاً طبياً. لا تشمل المرحلة 22 مرتجعات الموردين أو بوابة دفع أو chargebacks أو تعدد الفروع أو شحن المرتجع أو recall.

## تكامل المرحلة 23

يمكن الاسترداد إلى محفظة العميل المعرفة. ينشأ قيد محفظة مطابق، وتعكس نقاط الكسب وتستعاد النقاط المستبدلة بنسبة القيمة المرتجعة دون تعديل التاريخ الأصلي. راجع [`loyalty_wallet.md`](loyalty_wallet.md).

## الفروع والمؤسسات

يحمل المرتجع مؤسسة وفرع المصدر، وتتحقق الخدمات من تطابق الطلب أو بيع POS والعميل والدفاتر المالية قبل أي أثر. تعود الكمية إلى فرع المصدر وبنفس التشغيلة أو عهدة الحجر. تعرض API قراءة مرتجعات المؤسسة فقط، وتجمع التحليلات الأسباب والتصرفات والاستردادات والقنوات والفروع دون ملاحظات سريرية.
